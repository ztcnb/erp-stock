# 部署指南

## 一、环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17+ | 后端编译与运行 |
| Maven | 3.6+ | 后端构建 |
| Node.js | 18+(建议 20+) | 前端构建 |
| PostgreSQL | 14+(开发使用 16) | 数据库 |

## 二、初始化数据库

```bash
# 1. 创建数据库(已存在可先 DROP)
psql -h 127.0.0.1 -U postgres -c "CREATE DATABASE erp_stock ENCODING 'UTF8'"

# 2. 导入表结构与种子数据(脚本可重复执行,先删表再重建)
psql -h 127.0.0.1 -U postgres -d erp_stock -v ON_ERROR_STOP=1 -f sql/init.sql
```

Windows PowerShell 下建议先设置客户端编码,避免中文乱码:

```powershell
$env:PGCLIENTENCODING = "UTF8"
```

## 三、后端

### 开发运行

```bash
cd backend
mvn spring-boot:run
```

默认监听 `9102` 端口,context-path 为 `/api`。数据库连接、JWT 密钥与有效期在 `backend/src/main/resources/application.yml` 中配置:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://127.0.0.1:5432/erp_stock
    username: postgres
    password: postgres
erp:
  jwt:
    secret: <生产环境务必更换为随机长密钥>
    expire-hours: 24
```

### 生产构建

```bash
cd backend
mvn package -DskipTests
java -jar target/erp-stock-backend-1.0.0.jar
```

可通过命令行覆盖配置,例如:

```bash
java -jar target/erp-stock-backend-1.0.0.jar \
  --server.port=9102 \
  --spring.datasource.password=xxx \
  --erp.jwt.secret=xxx
```

## 四、前端

### 开发运行

```bash
cd frontend
npm install
npm run dev
```

默认监听 `5302` 端口,`/api` 请求由 Vite 代理到 `http://127.0.0.1:9102`(见 `vite.config.ts`)。

### 生产构建

```bash
cd frontend
npm run build   # 先执行 vue-tsc 类型检查,再产出 dist/
```

构建产物为纯静态文件,可用 Nginx 托管并反向代理后端:

```nginx
server {
    listen 80;
    server_name erp.example.com;

    # 前端静态资源
    location / {
        root /opt/erp-stock/dist;
        try_files $uri $uri/ /index.html;   # history 路由回退
    }

    # 后端接口(后端自带 /api context-path,直接透传)
    location /api/ {
        proxy_pass http://127.0.0.1:9102;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 五、验证部署

1. 打开首页跳转登录页,使用 `admin / 123456` 登录;
2. 看板出现指标卡与三张图表(数据来源为种子数据);
3. 走一遍业务链:新建采购单 → 审核 → 入库 → 实时库存数量增加 → 新建销售单 → 审核 → 出库 → 库存减少、流水与应收生成。

## 六、常见问题

- **端口被占用**:修改 `application.yml` 的 `server.port` 或 `vite.config.ts` 的 `server.port`(注意同步修改代理目标);
- **数据库连接失败**:确认 PostgreSQL 已启动、账号密码正确、`erp_stock` 库已创建;
- **重置演示数据**:重新执行 `sql/init.sql` 即可(脚本自带 DROP,并会重置序列);
- **本机有 HTTP 代理**:用 curl 调试本地接口时需绕过代理,如 `curl --noproxy '*' http://127.0.0.1:9102/api/...`。
